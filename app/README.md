# Silent Expiry Guardian: web app (Member 1 built)

One Google Apps Script web app for Alpha Electronics Sdn. Bhd. (fictional). This version contains **Member 1: Supplier Registration & Document Management**, plus the shared database and page shell that every module plugs into. The other four pages are placeholders for Members 2–5.

## Files

| File | Owner | What it does |
|---|---|---|
| `00_Config.gs` | Member 5 (shared) | Tab names, column headers, status values and upload limits. Everyone keeps it identical. |
| `01_Database.gs` | Member 5 (shared) | Sheet helpers, IDs that are never reused, dates in Malaysia time, locking, the audit log, the hand-off to AI extraction and `SEG_setupDatabase()`. |
| `02_App.gs` | Member 5 (shared) | `doGet()` serves the dashboard. |
| `M1_Suppliers.gs` | **Member 1** | Every server function for registration, checklists, uploads and document history, plus tests. |
| `M1_DemoDataset.gs`, `M1_DemoDatasetData.gs` | **Member 1** | One-click import of the fictional test dataset (`../dataset`): suppliers, their PDFs and the GroundTruth answer key. The data file is generated by `dataset/build_dataset.py`. |
| `Index.html`, `Styles.html`, `AppClient.html` | Member 5 (shared) | Page shell: sidebar with the 5 pages, styling, navigation, dialogs, toasts. |
| `M1_Page.html`, `M1_Client.html` | **Member 1** | The Supplier & Document Management page. |
| `appsscript.json` | Member 5 | Malaysia time zone, and the web app runs as you, for you only. |

`../dev/` holds development-only tools that are **not** pasted into Apps Script: a local preview and offline tests.

## Set it up in Google (about 15 minutes)

1. **Create the database.** In Google Drive, create a new Google Sheet called `Silent Expiry Guardian - Database`.
2. **Open Apps Script.** In the Sheet, click **Extensions → Apps Script**.
3. **Project settings.** Click the gear icon:
   - Set the time zone to **(GMT+08:00) Kuala Lumpur**.
   - Tick **Show "appsscript.json" manifest file in editor**.
4. **Add the files.** Back in the editor:
   - Open `appsscript.json` and replace its contents with ours.
   - Click **+ → Script** for each `.gs` file: `00_Config`, `01_Database`, `02_App`, `M1_Suppliers`.
   - Click **+ → HTML** for each `.html` file: `Index`, `Styles`, `AppClient`, `M1_Page`, `M1_Client`. Type the names without `.html`.
   - Paste each file's contents in, replacing what's there, then save.
5. **Create the tabs.** Choose `SEG_setupDatabase` in the function dropdown and click **Run**.
   - The first time, Google asks for permission. Click **Review permissions**, choose your account, then **Advanced → Go to (project)**. The warning appears because the script is yours and unpublished.
   - This creates all 13 tabs, a Drive folder for supplier documents, and the starting categories and document types.
6. **Test it.** Run these one at a time and read the **Execution log** underneath. Every line should say PASS.
   1. `test_M1_rules` checks the rules, without touching your data.
   2. `test_M1_endToEnd` registers a supplier named `TEST BrightClean Sdn. Bhd.`, uploads, renews and refuses a duplicate, using the real Sheet and Drive.
   3. `M1_removeTestSuppliers` removes the TEST supplier again. Its Drive folder goes to the bin, so it can be restored.
7. **Load the test dataset (optional).** The steps are in [dataset/README.md](../dataset/README.md):
   1. Upload `dataset/pdfs` to Drive.
   2. Add the script property `DATASET_FOLDER_ID`.
   3. Run `M1_importDemoDataset`.

   This registers 7 fictional suppliers with 17 documents and fills the GroundTruth tab. BrightClean is left out so you can register it live in the demo.
8. **Deploy.** Click **Deploy → New deployment**, choose the type **Web app**, keep **Execute as: Me** and **Who has access: Only myself**, then click **Deploy**. Open the web app URL it gives you.
   - While developing, **Deploy → Test deployments** gives a URL that always runs your latest saved code.

## What Member 1's page does (spec section 6)

| Spec feature | Where it is |
|---|---|
| 1. Register supplier | **Add existing supplier**, step 1. IDs (`SUP001`…) are assigned on first save and never reused. A duplicate registration number is refused. |
| 2. Dynamic categories | Step 2. The 5 categories and their suggested documents live in the `SupplierCategories`, `DocumentTypes` and `CategoryRequirements` tabs, not in code. Edit them in the Sheet. |
| 3. Configurable requirements | Step 3, or **Edit document checklist** later. You can:<br>• add documents, including the same type twice with a label<br>• mark each one mandatory or optional<br>• remove optional ones<br>• set reminder days<br>• set a review date for documents with no expiry.<br>The result is saved per supplier in `SupplierRequirements`. |
| 4. Guided registration | The 5-step wizard. **Save as draft** works on steps 1–3, and drafts can be continued from the list. |
| 5. Document upload | Step 4, or the supplier page. There is one upload button per required document, and you can also drag and drop. Files are checked as follows:<br>• Only PDF, PNG and JPG are accepted, up to 10 MB.<br>• The contents must really match the file type.<br>• The same file can't be uploaded twice.<br>Each file is saved in the supplier's Drive folder and recorded in `Documents`. |
| 6. Incomplete registration | `DRAFT` → `PENDING_DOCUMENTS` → `PENDING_VERIFICATION` → `ACTIVE_MONITORING`. A supplier with a missing mandatory document can't get past `PENDING_DOCUMENTS`. This status shows registration progress, not compliance. |
| 7. Document history | **Upload renewed version** makes version 2 the current one. Version 1 stays as `SUPERSEDED`, linked both ways, and is never deleted. **Version history** lists every version with a link. |
| Audit trail | Every save, upload, refused upload, renewal and status change goes to `AuditLog`. It appears as **Activity** on the supplier page. |

## How the documents are filed in Google Drive

Each supplier gets its own folder, split by document type:

```
Silent Expiry Guardian - Supplier Documents/
  SUP001 - BrightClean Sdn. Bhd./
    1. Contracts & Agreements/      DOC001_CLEANING_SERVICE_AGREEMENT_v1.pdf
    2. Licences & Permits/          DOC003_BUSINESS_REGISTRATION_RECORD_v1.pdf
    3. Certificates & Insurance/    DOC004_INSURANCE_CERTIFICATE_v2.pdf
      Old versions/                 DOC002_INSURANCE_CERTIFICATE_v1.pdf
```

- **Current documents** sit in their type folder.
- **Renewals:** when a renewed version is uploaded, the replaced file moves into that type's `Old versions` folder. Nothing is ever deleted.
- **Where to change the folder names:** `M1_DRIVE_FOLDERS` in `M1_Suppliers.gs`.
- **"Open Drive folder"** on a supplier's page opens this folder.

## Hand-off to the other members

Nobody uploads a PDF twice. Member 1 records each file once, and the other modules read it through these functions:

| Function | Who uses it | Returns |
|---|---|---|
| `M1_getDocumentsAwaitingExtraction()` | Member 2 | Current documents with no successful extraction yet, each with its Drive `fileId` and `documentClass`. |
| `M1_getSupplier(id)` | Members 2, 4 | Supplier details in the shared contract's shape. Member 2 compares names; Member 4 uses the contact details. |
| `M1_getSupplierRequirements(id)` | Member 3 | The checklist, used to detect `MISSING` documents. |
| `M1_getDocuments(id)` | Members 3, 5 | Every version of every document. |
| `M1_refreshRegistrationStatus(id)` | Member 5 | Call this after an extraction finishes, so the supplier can move to `ACTIVE_MONITORING`. |

**How extraction gets started.** After each upload, `SEG_requestExtraction()` runs.
- Once Member 5 adds a function called `M5_processExtractionQueue()`, it schedules that function to run about a minute later, so uploads never wait for Gemini.
- Member 2 counts a document as read when it writes an `Extractions` row with `processing_status` `EXTRACTED` (or `CORRECTED`) and the same `file_id`.

## Try it without Google

```bash
node dev/run-tests.js
```

```bash
node dev/build-preview.js
```

- `run-tests.js` runs the same tests as the Apps Script editor, plus 27 extra checks, against in-memory stand-ins for Sheets and Drive. The extra checks include importing the full dataset and the BrightClean live demo.
- `build-preview.js` writes `dev/preview.html`. Open it in Chrome or Edge to click through the real pages, loaded with the test dataset's 7 suppliers. Everything resets when you reload.

## Known limits
- **Single account.** One demonstration account runs everything. There is no role-based access control yet.
- **10 MB per file.** Files travel from the browser as text (base64), so 10 MB per file is the practical limit.
- **Exact duplicates only.** The duplicate check compares exact file contents. A re-scanned copy of the same paper is a different file, so it is accepted.
- **Links need access.** "View file" opens the file in Google Drive, so it works only for accounts that can see the folder.
- **Not yet run in real Apps Script.** So far it has been tested only with the offline stand-ins.
